The problem

Everyone ships "done."
Nobody ships proof.

"It works" is the most expensive sentence in software. Three failure modes the standard kills on contact:

FAIL_01

The vibes demo

One cherry-picked run, one lucky seed, declared victory. Single runs prove nothing — variance hides in the noise floor.

FAIL_02

The gaming procedure

Optimize the scoreboard, not the outcome. Goodhart's law ships to production and the real metric never moves.

FAIL_03

The strawman baseline

"We beat the naive approach." Against a weak baseline, anything looks like genius. A fair fight needs a tuned opponent.

The standard

Six gates. All must pass.
One failure = no commit.

The judge() runs every candidate through all six — automatically, before anything is allowed to be called done.

GATE 01 — COMMIT

Frozen before the evidence exists

Both procedures are fingerprinted and committed before the sealed test seed is drawn. No post-hoc tuning, no moving goalposts.

GATE 02 — PARITY

Same instances, same budget

Candidate and baseline see identical instances with identical compute budgets. random.Random(1) for both. No resource cheating.

GATE 03 — PLACEBO

Gain must come from the instance

Scored against mismatched hidden truths. If the gain survives a placebo, it's just the prior — not skill.

GATE 04 — PAIRED WIN

Statistically significant, effect-sized

Bootstrap lower confidence bound on the paired difference must clear zero. Bonferroni-corrected across slices. Luck doesn't pass.

GATE 05 — GOODHART

Truth gain must not lag proxy gain

If the optimizable proxy improves faster than the sealed truth signal, the procedure is gaming its own scoreboard. Flagged, not shipped.

GATE 06 — COST

No winning by burning compute

Candidate runtime is held against a slack multiple of the baseline. Victory by brute force is a cost failure, not a win.

How the loop runs

Stop only when the gate passes.

The standard is a loop, not a report. spec → plan → test → build → verify → review → commit — and verify has teeth.

1

Commit before you see the test

Both procedures are fingerprinted. The sealed seed is derived from the commit hash plus fresh entropy — drawn after the code is frozen. Tuning after the fact is structurally impossible.

2

Run the six gates on real outcomes

Every truth() score comes from an outcome that actually happened. Synthetic inputs, if any, are labeled. Mocked runs fail by definition — the placebo gate catches them.

3

Five fresh seeds, then the frozen holdout

GOLD must hold on five independent seeds — a single lucky pass never counts. Then one final run on a holdout set the procedure has never touched. All six, or the loop continues.

4

Commit with the receipt attached

The full report — wins, losses, flags, bounds, cost — ships with the commit. The receipt is the deliverable. "Trust me" is not a deliverable.
